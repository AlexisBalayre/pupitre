# Writing the design note and the one-slice brief

Both are comments on the issue, and both end in `pup plan add` tasks. A worker starts from its task, not from the issue, so a slice's goal and criteria must stand alone. Decision 187 has a task carry a copy of its ticket, but no command writes the ticket yet, so today the brief reaches the worker only through the task's goal and `--accept` criteria.

- **Design note** (a feature, or any issue a design trigger fires on): the slice list, one entry per slice with its goal, files, size and the slices that block it. Slices whose files overlap get a dependency edge, so one merges before the other starts (decision 176). The operator reviews it and adds `design-approved`.
- **One-slice brief** (nothing triggers a design): one entry, the same fields, no review.

## Principles

**Durability over precision.** An issue may sit for weeks while the code moves. Describe interfaces, types and behavioural contracts; name the type or command to look for. Do not cite line numbers, and treat file paths as the slice's scope-in, not as the description.

**Behavioural, not procedural.** Say what the system does, not how. Good: "`pup plan add` with no `--scope` exits 2 and prints `scope is required`." Bad: "add an `if` on line 42 of the handler."

**Complete, testable criteria.** Each criterion names a start state, an action and an observable result, and a test could assert it without asking the author. "Triage works correctly" is not one.

**Explicit scope boundaries.** State what is out of scope, so the worker does not gold-plate or touch a neighbour.

## Template

```markdown
> *This was generated by AI during triage.*

## Design note

**Slice 1: <title>** (small | medium | large)
- Goal: the behaviour it makes work, and the decision number it records, if any.
- Scope-in: the files it edits, including the tests that encode a contract it changes.
- Blocked by: none | slice N.
- Criteria:
  - [ ] testable criterion
- Out of scope: the neighbouring behaviour that stays as it is.
```

A one-slice brief is the same block under the heading `## Brief`. For a bug, slice 1's first criterion is the failing test that reproduces it.
